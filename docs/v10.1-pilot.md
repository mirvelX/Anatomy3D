# v10.1 alpha: acquired vertebral mesh pilot

This release adds actual licensed BodyParts3D atlas surfaces to the existing
schematic atlas. It starts the detailed-model milestone; it does not complete
anatomical validation or fine segmentation. Use the C1, C2 or L3 shortcut and
the model-source selector. All existing study structures remain in schematic mode.

## Candidate comparison

- **Direct BodyParts3D (selected):** individual vertebrae with exact identities,
  original common coordinates and explicit in-file licenses. Acquisition is
  described by the archive as CAD; this is a reduced atlas, not photogrammetry.
  [Original study](https://pubmed.ncbi.nlm.nih.gov/18835852/) describes an adult
  male whole-body anatomical model. Do not describe this as patient-specific,
  a clinically validated scan, or high-resolution photorealism.
- **UBC lumbar photogrammetry (not shipped):** Connor Dunne, University of
  British Columbia, [official page](https://www.clinicalanatomy.ca/back/vertebra3D.html),
  embedded Sketchfab ID `8dc6d9500ae344fe94c543f074c0825b`. The page's footer
  is CC BY-NC-SA 4.0, but a downloadable file-level grant and L3 identity were
  not established. A page-wide license is not enough to assume both.
- **Z-Anatomy (not shipped):** [upstream license and attributions](https://github.com/Z-Anatomy/Models-of-human-anatomy/blob/master/License.txt)
  declare CC BY-SA 4.0 with BodyParts3D lineage and other components under
  different terms, including NC models. No unverified all-assets license was
  applied to vertebrae; the direct source was sufficient for this pilot.

## Segmentation scope and review status

Original triangles are partitioned into stable structure IDs and an explicit
`unsegmented` remainder. No triangles are discarded, duplicated or generated.
The draft regions were chosen after inspecting orthographic source views and
compiled to face-index lists by `scripts/prepare-pilot.py`. This script uses
coarse geometric regions in source millimetres: it is **not a medical
segmentation algorithm or a completed manual dissection**. Runtime displays
the saved masks; it never guesses structure labels. The UI calls out the
approximate boundaries, and the masks retain a draft/not-expert-validated status.

- C1: anterior arch, posterior arch, lateral masses, transverse processes.
- C2: dens, body, spinous process, transverse processes.
- L3: body, spinous process, transverse processes.

Highlight, opacity, isolation and illustrative separation work on these 11
draft regions in both renderers. The bilateral regions are grouped, not
independently validated left/right masks. An isolated region is an open surface
patch of the original bone, not a closed detached anatomical object.
The unsegmented remainder is visible as context but is not a scored quiz target.
Articular surfaces, dens facets, tubercles, pedicles/laminae and accessory /
mammillary processes have not been separately approved or segmented here.
For these, the learner can explicitly return to the labeled schematic view.
Spaces are not falsely filled with solid anatomy in mesh mode.

## Neighbor / articulation foundation

All bones use one source-to-display transform: `[X, Z, Y] / 20`, after subtracting
the target's source-space bounding-box center. Twenty source millimetres equal
one display unit. This is an axis swap/reflection for the existing renderer;
triangle normals are recomputed. Every bone shares the same transform, so
relative position, dimensions and source spacing are preserved. There is no
independent normalization, generated disc, guessed contact alignment or repair.

C1-C2-C3 and L2-L3-L4 can be inspected in their source relationship. Occiput
is explicitly omitted in this pilot. C1 rotation is disabled because facet
contacts, pivot landmarks, collisions and movement limits have not been
validated. The separation slider is an exploded teaching view only.

Next articulation work requires independently reviewed articular face masks,
paired attachment points/normals, contact-gap and penetration tests, and an
appropriately sourced motion model. Native source placement is a foundation,
not evidence that all joints contact correctly.

## Compatibility and release verification

- No progress-key or schema migration is needed. The v10 schema stores an
  optional `meshMode`; older backups default to schematic. v9/v8/v7 migrations,
  learned structures, quiz scores and backup validation stay intact.
- Meshes, masks, attribution and manifest are included in immutable release
  hashing and service-worker precaching. A release remains fully usable offline.
- SHA-256 checks reject modified asset bytes or mismatched masks. Loading errors
  leave an explicitly labeled schematic fallback with a retry action.
- Existing unit checks cover all 104 schematic assembly combinations. New
  checks cover exact source hashes, partition coverage, invalid geometry,
  source-coordinate preservation and all pilot assembly combinations.
- Browser checks cover existing progress/PWA behavior, both renderers, five
  views, mesh picking, isolation/separation, quizzes, offline reload, retry and
  a 412px touch viewport. A physical Galaxy S23 Ultra was not available.
- CI and Netlify preview must succeed before merge. The owner authorized
  publication after successful checks in the follow-up request on 2026-09-28.
  That supersedes the previous request to await another production approval.

Expert validation and precise fine segmentation remain outstanding. Version
10.1 alpha intentionally makes those limitations visible; it must not be
advertised as a fully anatomically validated release.
